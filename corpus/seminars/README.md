# Память пройденных семинаров

Этот каталог — короткая переносимая память методов, а не архив исходных
сообщений. Сырые файлы пользователь кладёт локально в
`references/seminar/YYYY-MM-DD.txt`; они не входят в Git. После проверки
каждая задача превращается в одну строку `index.jsonl`.

Обязательные поля записи:

- `id` — стабильный содержательный идентификатор;
- `date` — дата официального семинара в формате `YYYY-MM-DD`;
- `status` — `verified`, `partial` или `raw`;
- `text` — обезличенная самодостаточная формулировка;
- `method` — один основной метод;
- `micro_methods` — малые шаги до основной теоремы;
- `signals` — признаки, по которым метод узнаётся;
- `prerequisites` — необходимые уже пройденные темы;
- `verification` — чем проверен результат;
- `source` — путь к официальному или внутреннему обезличенному разбору.

В подбор аналогов попадают только записи `verified`. Дата нужна для порядка
прохождения курса и не является датой личного сообщения. Имена, группы,
аккаунты, оценки и частные формулировки не сохраняются.

Карточка обязана описывать не только глобальный класс, но и малые приёмы.
Например, недостаточно написать «нерегулярность»: нужно добавить
«расставить скобки в логическом условии», «проверить дополнение», «подобрать
семейства левых и правых контекстов».

Полный процесс пополнения и контрольный список описаны в
`docs/SEMINAR-KNOWLEDGE.md`.
