# Незакрытые задачи tfl-solver

Здесь перечисляется только реально незакрытое. Текущие числа тестов и eval
находятся в `PROJECT-STATE.md`. Версия 1.0 завершена и работает в режиме
сопровождения: этот список не является требованием бесконечно расширять агент.

Статусы разделены принципиально:

- **внешнее ожидание** — нет опубликованного условия или доступа;
- **исследование** — известна математическая граница, но нет общего решателя;
- **намеренная граница** — полный автоматический ответ в общем случае
  невозможен или не нужен текущему курсу.

## P0 — внешнее ожидание: курс 2026

Формат контроля зафиксирован в `docs/COURSE-2026.md`, но в корпусе пока нет:

- полных условий четырёх лабораторных и рубрик оценивания;
- номера лабораторной с защитой и точного правила замены её баллов ЛР4;
- полной базы карточек РК и правил тренировочного таймера;
- примеров обеих частей экзамена и критериев разбора ошибочного ИИ-решения.

При публикации полного условия любой ЛР-2026 приоритет немедленно переходит к
самой лабораторной: автономный проект, тесты, описание, раскрытие использования
ИИ и подготовка к защите. Общая разработка агента в этот момент не продолжается.

Big Pharma не входит в актуальный курс. Старые задачи `PHARMA` сохранены только
как исторические регрессии.

## P0 — сквозная проверка LLM

Holdout v1 содержит семь задач 2021–2025. Harness, JSON Schema, runners
Codex/Claude и scorer готовы. Полный Codex baseline снят: 7/7 случаев прошли
порог, а доказательства пяти новых результатов проверены вручную. Остаётся:

- повторить Claude smoke после появления разрешённого аккаунта: текущий
  внешний запуск останавливается до первого tool call с 403
  `oauth_org_not_allowed`;
- после публикации материалов 2026 создать holdout v2 со слепыми задачами.

Ограничение числа команд уже исполняется, но вывод о влиянии на wall-clock и
стоимость потребует нескольких однородных повторов, а не одной пары запусков.

## P1 — предметные исследования

### Завершимость SRS

Для архивных вариантов 10, 16, 17, 18, 21, 22, 24, 26 и 27 не найдено
доказательства завершимости или цикла. Для вариантов 11 и 15 есть только
исчерпывающие проверки на фиксированных длинах. Уже применены петли, линейные,
матричные и арктические интерпретации, пары зависимостей, rule removal,
match bounds и ограниченный перебор. Следующие направления — более сильные
интерпретации/SMT и отдельный анализ length-preserving выводов.

Это исследовательский хвост старых условий, а не дефект команды
`tfl srs critical-pairs`: критические пары конечной строковой SRS теперь
вычисляются точно.

### Минимальная эквивалентная SRS

Нет общего полного метода для конечного множества нормальных форм. На архивном
варианте 20 Knuth–Bendix расходится, а стабилизация наблюдаемого числа классов
остаётся эвристикой. Нужен независимо проверяемый конечный свидетель либо
доказательство невозможности сокращения.

### Шаблонные системы переписывания

Текущий `tfl/pattern.py` даёт честный ограниченный поиск. Для положительного
доказательства локальной конфлюэнтности правил с переменными всё ещё нужны
символьная унификация и решение соответствующих словных уравнений. Конечный
поиск контрпримеров не заменяет такого доказательства.

### ЛР4

Точная принадлежность строк для capture/backreference, recursive expression
reference и lookahead реализована в `tfl.extre.exact_matches`; многопроходная
семантика 2025 имеет отдельный `stateful=True`. Остаётся только привязать
полный сценарий нечётных вариантов с атрибутными грамматиками к новому
официальному условию, если он войдёт в ЛР-2026.

В напечатанном архивном варианте 28 есть несогласованная закрывающая скобка в
выражении `^((?:a|b)*)a\1((?:a|b)*)b\2)+$`. Агент не должен молча угадывать
исправление; требуется официальное уточнение исходной формулы.

### Теория

- механизировать применение ping-pong lemma после появления задач, где это
  сокращает решение;
- восстановить точное условие примера 1.78: в доступных материалах есть только
  ссылка на номер;
- после новых лекций сопоставлять определения и нумерацию с текущим корпусом.

## P2 — улучшения покрытия, не блокирующие 1.0

- Улучшить поиск нижней границы минимальности NFA, когда найденный fooling set
  меньше построенного автомата. Любой результат остаётся нижней границей:
  fooling-set метод сам по себе не обязан быть точным.
- Сопоставить схемы ЛР5 через неподвижные точки с независимой реализацией
  RNGLR, если ЛР5 вновь появится в курсе.
- Повторить внешнюю сверку десяти грамматик в Grammophone при наличии
  стабильного официального интерфейса; внутренние тесты уже воспроизводимы.
- Улучшать положительные стратегии Conway–Krob и неограниченного delay только
  на конкретных новых задачах.
- Многосимвольные терминалы, LR(1)/LALR(1), TAG и VPL добавлять при появлении
  реального задания, а не ради формального охвата тем.

## Вопросы, требующие официального уточнения

1. Семантика lookbehind в курсе относительно стандартной семантики.
2. Квантификация в напечатанной Jumping Lemma.
3. Нулевая строка и стратегия префиксов в NL*.
4. Буквальная семантика ортогонального лабиринта.
5. Предполагаемый термин в вопросе Conway–Krob.
6. Точная конструкция LL(1)-аппроксимации.
7. Исправления к формулировке представления Шютценберже.
8. Недостающее продолжение материала про алгоритм Блюма–Коха.
9. Исправленная расстановка скобок в архивном варианте ЛР4 № 28.

## Намеренные границы

Следующие ручные исходы сами по себе не являются дефектом агента:

- доказательство детерминированности языка или невозможности real-time PDA в
  общем случае;
- изобретение контрпримера к замыканию без ограниченного семейства кандидатов;
- общий тест семилинейности образа Париха по произвольному предикату;
- вывод общего утверждения из конечного перебора.

Корректный результат для таких задач — содержательный ручной план, проверенные
частные случаи и явно обозначенное недоказанное обязательство.

## Завершённый аудит источников

Корпус содержит 117 уникальных PDF после хеш-дедупликации: 110 с пригодным
текстовым слоем, 3 с ненадёжным OCR и 4 без текста. Все 49 страниц сводного
конспекта и все 33 страницы SCAN/OCR-наборов просмотрены по рендерам. Итоги и
безличная предметная выжимка находятся в `corpus/knowledge/SCAN-REVIEW.md`.
Повторный сплошной просмотр не нужен; новые источники проходят тот же цикл
индексации, визуальной проверки и минимальной регрессии.
