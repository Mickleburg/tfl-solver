# Рецепт `LAB-3` — КС-языки: детерминизм, PDA, регулярные аппроксимации

Задание 2025: `FormalLanguageTheory/lab_tfl_2025_3.pdf`,
текст — `corpus/txt/FormalLanguageTheory_lab_tfl_2025_3.txt`.

Пункты задания и их цена:

| Пункт | Балл |
|---|---|
| Проанализировать язык на детерминизм; построить DPDA либо PDA без избыточного недетерминизма | основной |
| Обосновать **каждый** оставшийся недетерминированный переход накачкой | **+1** |
| Проанализировать язык на беспрефиксность | основной |
| Для детерминированного языка — проанализировать на LL-свойство | **+1** |
| Построить КС-грамматику (если язык задан словесно) и пересечь её с двумя регулярными аппроксимациями сверху | основной |
| Автоматическое тестирование эквивалентности распознавателей до и после пересечения | основной |
| Оформление в Markdown/LaTeX с формулами MathJax | **+1** |

## Вход

Варианты делятся пополам, и это меняет всю работу:

* **Нечётные** — дана грамматика. Файлы `evals/lab3_2025/variant-NN.cfg`,
  извлечены `tools/extract_lab3_variants.py`.
* **Чётные** — дано словесное описание языка (`evals/lab3_2025/languages.md`),
  грамматику надо построить самому. Задание прямо советует для LL-языка
  брать LL(k)-грамматику.

Номер варианта = номер в списке группы.

## Дерево решений

```
язык задан словесно?
├── да  → построить грамматику (см. §1), проверить её предикатом
│         tfl.parse.disagreements — иначе весь отчёт поедет
└── нет → грамматика дана; язык описать словами (это нужно для §2 и §3)

язык детерминирован?                      ← содержательный вопрос, оракула нет
├── да  → строим DPDA; проверяем tfl.pda.PDA.is_deterministic
│         └── язык беспрефиксен?
│             ├── да  → допуск по пустому стеку допустим
│             └── нет → допуск ТОЛЬКО по финальному состоянию
│         └── LL-свойство (+1 балл)
└── нет → строим PDA без избыточного недетерминизма;
          каждую оставшуюся развилку обосновываем накачкой (+1 балл)

в любом случае:
  LR(0)-автомат и LL(1)-автомат → пересечение по Бар-Хиллелу → сверка языков
```

Запуск: `python tools/lab3_report.py NN` (и `--pda my.pda`, когда автомат
построен; `--file my.cfg` для чётных вариантов).

## §1. Грамматика по словесному описанию

Строится содержательно, но **проверяется** машинно, и не проверять её нельзя:
ошибка здесь обесценивает всё остальное.

```python
from tfl.parse import disagreements
disagreements(grammar, predicate, "ab", max_len=10)
```

`predicate` пишется прямо по формуле из условия, независимо от грамматики.
Скажем, для варианта 12 (`|w₁|_aba = |w₂|_baa`) предикат перебирает все
разбиения слова на `w₁w₂` и считает вхождения — медленно, зато очевидно
правильно. Совпадение независимо написанных предиката и грамматики на всех
словах до длины 10 — настоящий довод; совпадение «по построению» — нет.

## §2. Детерминизм

**Оракула нет и быть не может**: эквивалентность КС-языков неразрешима,
детерминированность языка — тоже. Что даёт модуль:

* `PDA.nondeterminism()` — развилки построенного автомата с предъявлением
  конфликтующей пары переходов. Критерий из лекции 9: *если есть
  ε-переход, то он единственный, и других переходов из состояния нет*;
  переходов по одному символу — не больше одного.
* `PDA.accepts(word)` — симуляция с бюджетом, возвращает `Verdict`,
  а не `bool`.
* сверка автомата с грамматикой на всех словах ограниченной длины.

Главная ловушка формулируется так: **недетерминизм автомата ничего
не говорит о языке.** Из того, что ваш PDA имеет развилки, не следует,
что язык недетерминирован — вы могли просто построить неудачный автомат.
Вывод «язык недетерминирован» требует доказательства, обычно накачкой.

Обратное направление корректно: построили DPDA, `is_deterministic()`
подтвердил, сверка с грамматикой прошла — язык детерминирован.

## §3. Беспрефиксность

`tfl.parse.prefix_free(grammar, max_len)` возвращает **два** исхода из трёх:

* `False` — найдены `u` и `uv` (оба в языке), это полноценное опровержение;
* `None` — контрпримера до `max_len` нет; доказательством это не является.

«Да» модуль не возвращает никогда: беспрефиксность КС-языка — это пустота
`L ∩ L·Σ⁺`, неразрешимая. Доказывать беспрефиксность приходится
содержательно, обычно так: показать, что каждое слово языка однозначно
разбирается до конца (например, оканчивается маркером, который внутри слова
встречаться не может).

Зачем это в ЛР3: по пустому стеку DPDA распознаёт **ровно** беспрефиксные
детерминированные языки. Не беспрефиксен ⇒ допуск обязан быть по финальному
состоянию, и автомат с допуском по пустому стеку заведомо неверен.

## §4. LL-свойство (+1 балл)

Отвечать надо про **язык**, а спрашивать модуль умеет только про
**грамматику** — `CFG.is_ll1()`. Функции `language_is_ll1()` нет намеренно.

Полезные машинные факты для рассуждения:

* `CFG.left_recursive()` — левая рекурсия. Грамматика с ней не LL(k)
  ни при каком `k`, но язык может оставаться LL: рекурсия устраняется.
* `CFG.ll1_table()` — конфликтные ячейки; по ним видно, чем именно
  мешает грамматика.
* Необходимое условие: LL-язык детерминирован. Недетерминированность
  языка (доказанная, а не предположенная) сразу закрывает вопрос.

## §5. Регулярные аппроксимации сверху

Обе строятся одним приёмом: **берём магазинный распознаватель и забываем
стек**. Автомат без стека не проверяет, что возврат из нетерминала произошёл
туда, откуда был вызов, и разрешает вернуться в любое подходящее место —
язык от этого только расширяется.

* `tfl.approx.lr0_automaton` — позиционный, конструкция Перейры–Райта.
  Контрольная точка из лекции 9: язык `(ⁿ a )ⁿ` аппроксимируется языком
  `(* a )*`. Модуль этот пример воспроизводит (тест
  `test_nested_language_approximates_to_star`).
* `tfl.approx.ll1_automaton` — нисходящий двойник: состояния суть пункты
  `A → α•β`, ε-вызовы и ε-возвраты во все места вызова.

Перед пересечением обязательно проверить, что аппроксимация — надмножество
(`over_approximates` должен вернуть пустой список). Пересечение с «дырявой»
аппроксимацией молча отрежет часть языка, и отчёт выйдет правдоподобным,
но неверным.

## §6. Пересечение по Бар-Хиллелу

`tfl.approx.intersect(grammar, dfa)` даёт грамматику с нетерминалами
`⟨p, A, q⟩` — «из `A` выводится слово, переводящее автомат из `p` в `q`».
Именно в такой записи это делают в отчётах.

Наивный перебор промежуточных состояний даёт `|Q|ⁿ⁺¹` правил и на
грамматиках ЛР3 не проходит; модуль сначала считает неподвижной точкой
порождающие тройки и перебирает только по ним.

## §7. Тестирование эквивалентности

Задание требует «автоматическое тестирование предполагаемой
эквивалентности построенных распознавателей (до и после пересечения)».
В отчёте это три независимых пути к одному ответу:

| Распознаватель | Направление | Функция |
|---|---|---|
| Эрли | сверху вниз, исходная грамматика | `tfl.parse.recognize` |
| Кока–Янгера–Касами | снизу вверх, НФХ | `tfl.parse.cyk` |
| Перечисление языка | неподвижная точка | `tfl.parse.language` |

Плюс `equivalent_up_to(G, G∩M)` — сравнение до и после пересечения.
Смысл именно в независимости: совпасть «по построению» эти три не могут,
и каждое расхождение — настоящая находка. Ошибку в ε-правилах алгоритма
Эрли нашла ровно такая сверка.

## Что предъявить

1. Грамматика (данная или построенная) и, для чётных вариантов, проверка
   её предикатом по условию.
2. Вывод о детерминизме языка **с доказательством**, а не со ссылкой
   на вид автомата.
3. PDA: рисунок или таблица переходов; для DPDA — подтверждение
   детерминизма; для PDA — список развилок с парами слов и накачкой.
4. Вердикт о беспрефиксности с witness'ом либо с содержательным
   доказательством.
5. Для детерминированного языка — разбор LL-свойства.
6. Оба автомата-аппроксимации (`lr0.dot`, `ll1.dot`) и обе грамматики
   пересечения.
7. Протокол сверки: сколько слов проверено, сколько расхождений.

Всё в Markdown с формулами MathJax — это +1 балл.

## Известные ловушки

1. **Свойство грамматики выдают за свойство языка.** Самая частая
   содержательная ошибка: «грамматика не LL(1), значит язык не LL»,
   «в автомате есть развилка, значит язык недетерминирован». Оба вывода
   неправомерны.
2. **Допуск по пустому стеку при непрефиксном языке.** DPDA с таким
   допуском распознаёт только беспрефиксные языки; если язык не таков,
   автомат неверен независимо от того, как аккуратно он нарисован.
3. **Левая рекурсия и нисходящий автомат.** Автомат `from_cfg` на
   леворекурсивной грамматике раскрывает `S → S a S b` бесконечно.
   Симуляция спасается отсечением по минимальной выдаче стека
   (`PDA.min_yield`), но рассуждать по такому автомату о языке нельзя.
4. **«Не выяснено» принимают за «нет».** `PDA.accepts` возвращает
   `Verdict`; `bool(verdict)` намеренно бросает исключение. Слова,
   на которых бюджет исчерпан, в отчёте перечисляются отдельно —
   они проверку не проходили и не проваливали.
5. **Пересечение «подтвердило» язык.** Совпадение языков до и после
   пересечения на словах до длины 7 не доказывает, что аппроксимация
   точна; оно лишь не опровергает построение.
6. **Многосимвольные терминалы.** Правые части разбираются посимвольно
   (заглавная буква со штрихами — один нетерминал), потому что в условиях
   пишут и `S → b T a a T`, и `S → ab S bb S`. Токена `id` эта нотация
   не выразит.
