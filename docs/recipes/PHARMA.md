## Как решать: разобранные задачи каждой цены

### 1 балл. Минимальный ДКА (раздел A, 2021)

> Построить минимальный DFA, распознающий язык слов над `{a, b, c}` таких,
> что в них либо встречается хотя бы две буквы `c`, либо встречается
> хотя бы две одинаковые буквы подряд.

```python
from tfl.automata import dfa_of
from tfl.myhill import class_table

pattern = "(a|b|c)*c(a|b|c)*c(a|b|c)*|(a|b|c)*(aa|bb|cc)(a|b|c)*"
dfa = dfa_of(pattern, alphabet="abc").minimize()
len(dfa)                 # 7
print(class_table(dfa).to_markdown())
```

Семь состояний, и таблица классов сразу обосновывает минимальность.
Тот же язык стоит в разделе C задачей «построить синтаксический моноид»
на 1 балл: `syntactic_monoid(dfa)` даёт 15 элементов, моноид апериодичен.

### 1 балл. Регулярность языка со счётчиками (раздел B, 2021)

> Проверить, является ли регулярным язык
> `{w | w ≠ w₁aabw₂ & w ≠ w₁bbaw₂ & |w|_a = |w|_b}`

Условие `|w|_a = |w|_b` само по себе нерегулярно, поэтому первый порыв —
доказывать нерегулярность. Оракул говорит другое:

```python
from tfl.lang import from_predicate, from_regex, residual_growth

L = from_predicate(lambda w: "aab" not in w and "bba" not in w
                             and w.count("a") == w.count("b"), "ab")
residual_growth(L, max_prefix=8, suffix_len=8)
#   классов не меньше 3, кривая 1:2 2:3 3:3 3 3 3 3 — полка
L.words(8)          # ['', 'ab', 'ba', 'abab', 'baba', 'ababab', ...]
L.disagreements(from_regex("(ab)*|(ba)*", "ab"), 11)      # []
```

Язык — это `(ab)* ∪ (ba)*`, и он регулярен. Запреты `aab` и `bba`
заставляют буквы строго чередоваться, а равенство счётчиков добивает
чётность. Ответ на 1 балл — одна регулярка и объяснение в две строки.

**Мораль общая:** запрещённые подслова часто превращают нерегулярное
условие на счётчики в регулярный язык. Считайте кривую роста, прежде
чем строить накачку.

### 2 балла. Пополнение по Кнуту–Бендиксу (раздел F. модели, 2021)

> Произвести пополнение по Кнуту–Бендиксу SRS `gf → ff`; `fg → f`.

```python
from tfl.srs import parse_srs

srs = parse_srs("gf -> ff\nfg -> f")
srs.terminates().value            # True
srs.locally_confluent().value     # False — пара «fgf» не сходится
system, verdict = srs.complete(srs.find_shortlex_order())
print(system)     # fff → ff;  fg → f;  gf → ff
verdict.value     # True — все критические пары сходятся
```

Пополнение добавляет одно правило `fff → ff`. Критическая пара, из-за
которой оно понадобилось, — слово `fgf`: по `fg → f` получается `ff`,
по `gf → ff` получается `fff`.

### 3 балла. Когда пополнять нечего (раздел F. модели, 2021)

> Произвести пополнение по Кнуту–Бендиксу SRS `ba → ab`; `ab → bb`.

```python
srs = parse_srs("ba -> ab\nab -> bb")
srs.terminates().value            # True
srs.locally_confluent().value     # True — обе критические пары сходятся
```

Система уже сходящаяся: завершима и локально конфлюэнтна, а по лемме
Ньюмана этого достаточно. Ответ — «пополнять нечего», с предъявлением
обеих критических пар (`abb`/`bbb` и `bba`/`aab`) и их сведения.
Написать «пополнил» и выдать ту же систему — потеря балла.

### 5 баллов. Где оракул не справляется (раздел F, 2023 и 2025)

> Исследовать на завершаемость следующую SRS: `fg → gff`, `fh → hg`.

```python
parse_srs("fg -> gff\nfh -> hg").terminates()
#   None — ни петли, ни армейского порядка, ни линейной интерпретации
```

Расширенный поиск (наклоны до 5, сдвиги до 12, восемь миллионов
кандидатов) тоже ничего не даёт. Это честное «не выяснено»: нужен
более сильный порядок — рекурсивный по путям или матричная интерпретация
через SMT. Задача не зря стоит 5 баллов.

## Префиксные грамматики (раздел C, 2 и 4 балла)

Определение — лекция 4 курса 2022, слайд 31, дословно:

> Дана SRS `S` с правилами двух видов: `aᵢ → b₁…bₙ` и `aᵢ → ε`. Разрешим
> применять правила только к первым буквам слова. Пара `⟨S, w₀⟩`
> определяет алфавитную префиксную грамматику.
> **Утверждение.** Язык `L⟨S, w₀⟩` регулярен.

```python
from tfl.prefix import parse_prefix_grammar

apg = parse_prefix_grammar("a -> bb\nb -> a\nb -> ε", start="ab")
sorted(apg.collapsing())              # ['a', 'b']
apg.to_cfg()                          # линейная грамматика по лекции
apg.agrees_with_rewriting(max_len=7)  # сверка с прямым переписыванием
```

`to_cfg` — это конструкция из лекции, а `reachable` — прямое переписывание
первой буквы; написаны они независимо, и `agrees_with_rewriting` их
сверяет. Совпадение на всех словах до заданной длины и есть проверка
конструкции.

Ключевая деталь конструкции: фронт переписывания доходит до первой буквы,
которая **не коллапсирует**, и дальше не идёт никогда. Всё, что правее,
навсегда остаётся терминалами — отсюда линейность грамматики, а из неё
регулярность языка.

Префиксная грамматика нужна не только в «Аптеке»: это второе независимое
представление языка на задаче 2 РК1 (+2 балла), и на ней же стоит
следствие теоремы Турчина из лекции 6.

## Системы переписывания термов (раздел «F. КЗ-языки»)

Задачи «исследовать на завершаемость следующую TRS» повторяются
из года в год почти дословно: `F8` в 2021, 2022, 2023 и 2024,
`F6` в 2022, 2023 и 2024. Здесь переменные, а не строки, — работает
`tfl/trs.py`, а не `tfl/srs.py`.

**Переменные объявляются явно, и это не педантизм.** В корпусе живут
две противоположные договорённости: в issue #2 переменные строчные
(`F(q,q,q)`), а в «Аптеке» ровно наоборот — `variables = [X]`, и `E`,
`Q`, `W` это функциональные символы. Угадывать по регистру нельзя.

```python
from tfl.trs import parse_trs, parse_interpretation

system = parse_trs("""
    variables = [x, y]
    f(f(a, x), y) -> f(f(x, f(a, y)), a)
""")
system.terminates()
```

### Унарная система — это строки

> **F6 (2 балла).** `variables = [X]`, семь правил вида
> `E(Q(q(q(E(...(X)...))))) → Q(Q(W(q(...(X)...))))`

Все символы одноместные, значит цепочка `f(g(h(X)))` читается как слово
`fgh`, а подтерм с переменной внизу — это ровно подстрока. Такая TRS
и есть система переписывания строк:

```python
system.is_unary()     # True
system.as_srs()       # EQqqEEEWEEqWq → QQWqEWWEWEq, …
```

`terminates` делает этот переход сам, но переводить полезно и руками:
после него доступны армейский порядок, линейные интерпретации и весь
остальной строковый инструментарий.

### Полиномиальные интерпретации

Банк вопросов 2024 года приводит системы **вместе с интерпретациями**
(`f(x) := x+1; g(x,y) := x + y*2 + 1`), то есть спрашивает не «придумайте»,
а «проверьте». Проверка механическая:

```python
system.check_interpretation(parse_interpretation("f(x) := x+1; g(x,y) := x + y*2 + 1"))
```

Правило убывает, если у разности `[l] − [r]` все коэффициенты
неотрицательны, а свободный член строго положителен. Это достаточное
условие, а не критерий, и в отчёте пишут именно его.

**Проверенная находка.** Для правила `f(x) → g(x,x)` интерпретация,
выписанная в банке, правило **не уменьшает**: `[f(x)] = x + 1`,
а `[g(x,x)] = 3x + 1`. Сама система при этом завершима — в правой части
нет `f`, — и перебор находит для неё другую интерпретацию. Учтите, что
текст банка извлечён из PDF и мог пострадать при распознавании: часть
фрагментов там с несогласованными арностями (`g(z,g(z,z),z)` при трёх
аргументах у `g`).

### Критические пары и конфлюэнтность

Наложение ищется унификацией левой части одного правила с **не-переменным**
подтермом левой части другого:

```python
system.critical_pairs()
system.locally_confluent()
system.joinable(left, right)
```

Наложения в переменной критических пар не дают — туда подставляется что
угодно, и оба пути сходятся автоматически. Поэтому у `f(f(x)) → x`
критических пар нет вовсе, хотя левая часть накладывается сама на себя.

`joinable` возвращает три исхода, и это не формальность: у незавершимой
системы обход обрезается по размеру, и «общего потомка не нашли» —
не то же самое, что «его нет».

### Путевой порядок и пополнение

Завершимость термовой системы доказывается рекурсивным путевым порядком
(LPO): каждой букве сигнатуры назначается старшинство, и дальше термы
сравниваются по трём случаям определения. Порядок подбирается перебором:

```python
system.find_precedence()          # '0 plus s' либо None
system.lpo_terminates("0 plus s") # True — доказано; None — порядок не тот
```

Исходов у `lpo_terminates` два, а не три: убывание доказывает завершимость,
а его отсутствие не доказывает ничего.

Пополнение — `complete`, схема Юэ: очередь уравнений, ориентация по LPO
и **межредукция** после каждого нового правила (правила, левая часть
которых стала переписываемой, возвращаются уравнениями). Без межредукции
система пухнет: на аксиомах группы за пять раундов набегает сорок правил
вместо десяти.

```python
done, verdict = system.complete()      # порядок подберётся сам
done, verdict = system.complete("i f e")
```

Контрольная точка — свободная группа: `f(f(x,y),z) = f(x,f(y,z))`,
`f(e,x) = x`, `f(i(x),x) = e` пополняются до канонических **десяти**
правил, среди которых выведенные правая единица `f(x,e) → x`,
`i(i(x)) → x` и `i(f(x,y)) → f(i(y),i(x))`.

**Порядок символов — не деталь.** Первое же старшинство, ориентирующее
аксиомы (`f ≻ e ≻ i`), доводит дело до уравнения `i(f(x,y)) = f(i(y),i(x))`,
неориентируемого в нём ни в какую сторону. При `i ≻ f ≻ e` пополнение
сходится. Поэтому `complete` без аргумента перебирает кандидатов.

Неориентируемое уравнение — законный исход, а не сбой: `f(x,y) = f(y,x)`
не ориентируется **ни одним** порядком редукции, потому что обе части
получаются друг из друга подстановкой. Это и есть причина, по которой
существует пополнение по модулю AC.

### Что оракул не берёт

`F8` — `f(f(a,x),y) → f(f(x,f(a,y)),a)` — остаётся «не выяснено»:
ни петли, ни полиномиальной интерпретации с коэффициентами до 4.
Линейных интерпретаций там не существует в принципе: сравнение
коэффициентов при `x` и `y` даёт `β ≥ α` и `1 ≥ αβ`, откуда `α = β = 1`,
а тогда свободные члены требуют `0 > [a] + γ`. `F6` тоже не взялась.
Обе задачи стоят 2–3 балла, так что это ожидаемо.

## Унификация (ЛР1 2022, задача 1)

```python
from tfl.trs import unify, parse_term, substitute

names = {"q", "x", "y", "a", "w"}
mgu = unify(parse_term("F(q,q,q)", names),
            parse_term("F(F(x,y,R), F(a,w,a), F(w,x,y))", names))
#   q ↦ F(R, R, R),  x = y = a = w = R
```

Это разобранный преподавателем пример из issue #2, и ответ совпадает.
Форма записи у преподавателя другая — мультиуравнения `{q} := F(x,y,a)`,
`{x,a,w,y} = R`, — но унификатор тот же.

**Формулировка ЛР1 2022 требует конкретный алгоритм:**

> Нужен именно настоящий Мартелли–Монтанари, а не из википедии!
> Нам нужен **алгоритм 3**, а не алгоритм 1.

`unify_mm` реализует именно его — через мультиуравнения, общую часть
и границу:

```python
from tfl.trs import unify_mm, common_part, substitution_of, unified_term

system = unify_mm(t1, t2)
#   {⊤} = (F(q, q, q))
#   {q} = (F(a, w, a))
#   {a, w, x, y} = (R)
unified_term(system)      # F(F(R,R,R), F(R,R,R), F(R,R,R))
```

Разобранный в условии пример общей части воспроизводится дословно:
у `{x₁,x₂} = (f(g(x₃), h(x₄, g(x₅))), f(x₄, h(g(g(x₆)), x₇)))` общая
часть `f(x₄, h(x₄, x₇))`, граница `{x₄} = (g(x₃), g(g(x₆)))`
и `{x₇} = (g(x₅))`.

Две ловушки, обе отмечены преподавателем:

* **Общая часть обрывается на переменной.** Если в позиции стоит хотя бы
  одна переменная, конструктор туда не попадает, даже если у остальных
  термов он одинаковый.
* **Уравнения вида `{xᵢ, xⱼ} = ∅` в подстановку входят.** Общей части они
  не задают, шаг унификации к ним не применяется, но `xᵢ := xⱼ` они
  определяют, и про них забывают.

Проверка вхождения здесь выглядит иначе, чем в обычной унификации:
это шаг «выбрать уравнение, переменные которого не встречаются в правых
частях **никакого** уравнения вообще». Своё собственное — тоже: без этого
`{x} = (F(x))` некому забраковать.

`unify` считает тот же унификатор обычным способом; оба сверены
между собой на всех парах из набора образцов.

| `locally_confluent` вернул `True` при завершимости | **система сходящаяся** (лемма Ньюмана) |
| `complete` вернул `True` | **пополнение завершено**, все пары сходятся |
| `terminates` вернул `None` | ничего: диапазон порядков и интерпретаций конечен |
| моноид посчитан | **доказательство**: конструкция конечна и точна |

## Чего не делать

* Не браться за 5-балльную, не сняв 1- и 2-балльные: цена размечена
  по сложности, и она честная.
* Не доказывать нерегулярность, пока не посчитана кривая роста:
  запрещённые подслова регулярно превращают счётчики в чередование.
* Не выдавать исходную систему за пополненную: если пополнять нечего,
  так и надо написать, предъявив критические пары.
* Не переносить решение с TRS на SRS: у нас нет переменных, и это
  не мелочь, а другой класс задач.
