# Композиции регулярных языков и малые аргументы

Вход — полный автомат или выражение и разрешённые операции; выход — явные
автоматы аргументов, дерево формулы, размеры и проверка равенства языков.
Номер работы не определяет этот маршрут. При поставке проекта соблюдать
`docs/LAB-PROJECT-STANDARD.md` и фактическое раскрытие использования ИИ.

## Зафиксировать критерий

Сначала назвать единицу размера: максимум состояний одного аргумента,
сумма состояний, число переходов и размер записи — разные критерии.
Сохранить несколько недоминируемых кандидатов. Считать размеры и разных
аргументов, и всех их вхождений, если есть повторное использование.
«Лучший найденный» не означает доказанно минимальный.

Операции считать по дереву: бинарное объединение/конкатенация/перемежение
и унарная итерация/корень — по одному узлу. k-арное объединение требует
k−1 бинарных узлов. Повторённое подвыражение считается повторно.
Нельзя спрятать композицию за ссылкой на именованный макрос: ссылки ведут
только на явные автоматы. Автомат аргумента может распознавать сложный язык,
но весь его размер показывается. Семантику каскада и управляющую функцию
нужно задать отдельно; неподдерживаемый узел отвергается.

## Простой поиск

1. Проверить достижимость, мёртвое состояние и минимизировать исходный ДКА.
   Доказательство минимальности ДКА не доказывает невозможность меньшего НКА.
2. Сравнить короткие левые остатки. Если одна ветвь существенно сложнее,
   выделить префикс p: отдельно слова без p и слова p·v. Для хвоста проверить
   ε; разбиение по первой букве покрывает только непустые слова.
3. Для каждого выбранного языка сравнить ДКА без мёртвых состояний,
   остаточный НКА и обращение остаточного НКА обращённого языка.
4. Проверить каждую замену и всю композицию точно, затем испытывать фаззингом.
   При проигрыше по числу переходов показать это, даже если состояний меньше.

Остаточный кандидат:

```python
from tfl.nlstar import compact_residual_nfa
candidate = compact_residual_nfa(dfa, max_columns=10000,
                                 prune_covered_transitions=True)
```

Все разные множества состояний, принимающих суффикс, замыкаются прообразами
букв. Только после полного замыкания битовые строки точно задают включения
остаточных языков. Превышение бюджета даёт исключение, не частичный
сертификат. Конструкция минимальна среди остаточных автоматов, а не среди
всех НКА; синтетическое начальное состояние учитывать отдельно.

## Машинный контракт

`tfl/composition.py` использует только стандартную библиотеку и может быть
передан как автономный модуль. Формат: schema_version=1, alphabet,
arguments, formula. Аргумент — kind=dfa/nfa, states, start, finals,
transitions; ребро from/symbol/to, symbol=null для ε. Для входного ДКА
поддерживается оболочка dfa и необязательное trap_state.

Лист `{"ref":"A"}`; узел `{"op":"concat","args":[левое,правое]}`.
Поддержаны union, concat, star, shuffle, sqrt. Последний означает
`{w:ww∈L}`, не выбор половины длины. Нужно отслеживать преобразование
всего множества состояний после w, чтобы применить его второй раз.

```python
from tfl.composition import load_json, parse_machine, compile_document, compare
source, changes = load_json(source_text)  # строгий JSON по умолчанию
answer, _ = load_json(answer_text)
candidate, count = compile_document(answer, max_operations=5)
certificate = compare(parse_machine(source), candidate, max_pairs=1000000)
```

Повторные JSON-ключи и неверные переходы отвергаются. Удаление завершающей
запятой разрешено только явным allow_trailing_commas=True; сохранить
оригинальные байты, хеш и список изменений. Не исправлять формальный объект
по догадке. Решение должно быть строгим JSON даже при дефекте входного файла.

Точный обход пар подмножеств либо исчерпывает всё конечное пространство,
либо выдаёт кратчайшее различающее слово. BudgetExceeded означает неизвестный
исход. Фаззинг использует другой путь распознавания исходного объекта,
фиксированный seed, пустое слово, границы, длинные периодические слова и
мутации принимаемых примеров. Совпадение на испытаниях — не доказательство.

Полезные уроки для задач со счётчиками и разрезами:
`corpus/knowledge/REGULARITY-TRAINING.md`. Общая дисциплина та же: проверить
границу случая, доказать оба включения, отделить конечный эксперимент от
доказательства и не переносить вид задачи на другой формальный объект.
