# Агент для решения задач ТФЯ: архитектура, план разработки, критерии приёмки

Цель: получить воспроизводимый цикл, который по **новой** задаче (вариант РК,
лаба, экзаменационный билет, задача из «Аптеки») выдаёт решение в формате,
принимаемом преподавателем, с явно измеримой уверенностью в правильности.

---

## 1. Центральный принцип

> **Рассуждает LLM, решает арбитр.**

ТФЯ — редкая предметная область, где почти каждый промежуточный шаг
*исполним*. Автомат можно прогнать, грамматику — разобрать, SRS — переписать,
накачку — проверить перебором на конечном срезе. Поэтому агент строится не как
«умный решатель», а как **генератор гипотез с исполняемым оракулом**:

1. LLM выдвигает гипотезу («язык регулярен, вот ДКА»).
2. Исполняемый инструмент опровергает или не опровергает её на конечном срезе.
3. Только пережившая проверку гипотеза идёт в доказательство.

Это снимает главный риск: правдоподобное, красиво оформленное и неверное
решение. Ошибки в разборах старшекурсников (слой C) — ровно этого сорта.

## 3. Слой T — исполняемые оракулы

Пакет `tfl/`, чистый Python, без внешних зависимостей кроме `z3-solver`
(опционально) и `pytest`. Разбит по примитивам из таксономии, §6.

| Модуль | API | Обслуживает |
|---|---|---|
| `tfl/regex.py` | парсер академических регексов → AST; производные Брзозовски | `LAB-2`, `RK1-C` |
| `tfl/automata.py` | НКА/ДКА, детерминизация, минимизация (Хопкрофт), произведение, дополнение, `equivalent(A,B)`, `to_dot()` | всё |
| `tfl/myhill.py` | таблица классов эквивалентности; нижняя оценка размера НКА по Глайстеру–Шаллиту | `RK1`, `LAB-2`, `RK2` доп. |
| `tfl/cfg.py` | КС-грамматика, чистка, НФ Хомского, НФ Грейбах, First\_k/Follow\_k, LL(1)- и LR(0)-таблицы, конфликты | `LAB-3`, `EXAM-2` |
| `tfl/parse.py` | CYK, Earley, рекурсивный спуск с возвратами и мемоизацией | `LAB-3`, `LAB-4` |
| `tfl/pda.py` | PDA/DPDA, симуляция, CFG↔PDA | `LAB-3`, `RK2-A` |
| `tfl/attr.py` | интерпретатор атрибутных грамматик: перебор деревьев вывода до глубины `d`, вычисление атрибутов, проверка условий | `RK2-C`, `LAB-4` |
| `tfl/srs.py` | переписывание, поиск НФ, критические пары, локальная конфлюэнтность, Кнут–Бендикс, LPO и «армейский» порядок, поиск циклов | `LAB-1`, `RK2-A`, `EXAM-3` |
| `tfl/lang.py` | **язык как предикат**: `member(w) -> bool` из словесного описания, счётчики подслов, `enumerate(n)` | все проверки |
| `tfl/pump.py` | проверка накачки: для гипотезы «не регулярен/не КС» перебрать все разбиения свидетеля и подтвердить выпадение | `RK1`, `RK2`, `EXAM` |
| `tfl/fuzz.py` | генератор слов (из языка / не из языка), дифференциальное и метаморфное тестирование | все лабы |

**Ключевой инструмент — `tfl/lang.py`.** Он превращает словесное описание
языка в исполняемый предикат. Тогда любая гипотеза («вот ДКА для этого языка»)
проверяется сравнением на всех словах длины ≤ N: `{w : |w| ≤ N, A(w) ≠ L(w)}`.
Пустое множество расхождений при N = 12–14 — сильный сигнал.

## 4. Слой R — рецепты

Один файл на класс задач, `docs/recipes/<КОД>.md`. Структура каждого:

```
## Вход
## Дерево решений          — последовательность вопросов с ветвлением
## Оракул                  — какие функции tfl/ вызвать и в каком порядке
## Что предъявить          — точный перечень артефактов
## Разбалловка             — сколько стоит каждый артефакт
## Эталонные разборы       — ссылки на corpus/txt с номерами страниц
## Известные ловушки
```

Пример дерева решений для `RK1-B` (счётные ограничения):

```
1. Выписать все счётчики подслов, участвующие в условии.
2. Ограничена ли разность каждой пары структурно?
   (|w|_ab − |w|_ba| ≤ 1 всегда; |w|_a − |w|_b — не ограничена)
   ├─ да для всех → язык регулярен
   │    → ДКА: состояние = (последние k−1 букв, вектор разностей)
   │    → минимальность таблицей классов        [tfl.myhill]
   └─ нет хотя бы для одной → кандидат в нерегулярные
        → подобрать свидетеля с префикс-функцией 0
        → пересечь с регуляркой, изолирующей неограниченную разность
        → накачка                                [tfl.pump]
```

Приоритет написания рецептов: `RK1-B`, `RK2-C`, `LAB-1`, `LAB-2` —
самые частотные и самые механизируемые.

## 5. Цикл решения новой задачи (S0–S7)

**S0. Приём.** На входе — PDF/скан/текст. Извлечь условие
(`tools/extract_corpus.py`, для сканов `--render` + чтение глазами).
Зафиксировать: год, форма контроля, номер варианта, номера задач.
Определить код класса по таксономии. При неоднозначности — спросить.

**S1. Retrieval.** Найти в `corpus/txt/`:
похожую формулировку в других годах (`grep`), авторский разбор
(`RK1_probe_task_solutions`, `RK2_probe_tasks_solutions`), релевантный
раздел лекции, решение той же задачи в слое C. Всё найденное — как
контекст, **условие — только из слоя A**.

**S2. Рецепт.** Загрузить `docs/recipes/<КОД>.md`.

**S3. Формализация.** Записать задачу машинно: предикат языка в `tfl/lang.py`,
грамматику/SRS/АГ в соответствующем формате. **Проверка формализации:**
сгенерировать 20 коротких слов, вручную свериться, что предикат согласуется
с человеческим чтением условия. Ошибка здесь отравляет всё дальше.

**S4. Цикл гипотеза↔оракул.** Идти по дереву решений рецепта. На каждом
ветвлении — не «подумать», а *посчитать*: перебрать слова, прогнать автомат,
раскрутить АГ. Записывать в журнал каждую отвергнутую гипотезу — они пойдут
в отчёт как обоснование выбора.

**S5. Доказательство.** Только после того, как гипотеза пережила оракул.
Для нерегулярности/не-КС: свидетель уже найден численно, `tfl.pump`
подтвердил, что все разбиения ломаются — доказательство пишется по готовому
разбору случаев, а не выдумывается.

**S6. Оформление.** Markdown с LaTeX-формулами под MathJax (даёт +1 балл).
Автоматы — `.dot` + `.svg`. Структура отчёта — как в `boomhaa-tfl-labs/lab1/report_lab1.md`.

**S7. Самопроверка** по рубрике §6. Отчёт не считается готовым, пока не
проставлены отметки L0–L3.

## 6. Критерии проверяемости результата

Четыре независимых уровня. Уровень считается пройденным только целиком.

### L0 — формальная приёмка (дёшево, обязательно)

- [ ] Решена задача **своего варианта** (номер сверен с условием).
- [ ] Отвечены **все** пункты задания, включая пункты «+1 балл».
- [ ] Формат: `.md` с MathJax-формулами (или LaTeX). Формулы рендерятся.
- [ ] Автоматы приведены графически (`.dot`/`.svg`), а не только таблицей.
- [ ] Для лаб: тесты читают вход из потока/аргумента, **пути не захардкожены**;
      обрабатываются `\r\n` и хвостовые пробелы (требование `2023/README.md`).
- [ ] Отклонения от стандартного синтаксиса описаны в `readme.md` лабы.

### L1 — машинная проверка (главный уровень)

Каждое утверждение решения должно быть подтверждено исполнением.

| Утверждение | Чем проверяется | Критерий прохождения |
|---|---|---|
| «Вот ДКА для языка L» | `tfl.lang.member` vs автомат на всех `|w| ≤ N` | 0 расхождений при N ≥ 12 |
| «ДКА минимален» | `tfl.automata.minimize` + таблица классов | число состояний совпадает; таблица различает все пары |
| «НКА размера k минимален» | `tfl.myhill` — теорема Глайстера–Шаллита | найдена треугольная матрица размера k |
| «Регулярка ≡ автомат» | `tfl.automata.equivalent` через произведение с дополнением | язык разности пуст |
| «Язык нерегулярен» | `tfl.pump` на найденном свидетеле | **все** разбиения `xyz` с `|xy| ≤ p` дают выпадение |
| «Язык не КС» | `tfl.pump` (КС-вариант) на пересечении с регуляркой | все разбиения `uvxyz` ломаются |
| «Грамматика порождает L» | генерация + `tfl.parse` в обе стороны | ни одного слова из L не отвергнуто, ни одного не из L не принято, `|w| ≤ N` |
| «Грамматика LL(1)/LR(0)» | `tfl.cfg` таблицы | конфликтов нет; сверка с Grammophone |
| «PDA детерминирован» | `tfl.pda` | в каждой конфигурации ≤ 1 применимый переход, ε-переходы не конфликтуют |
| «SRS завершима» | `tfl.srs` + фундированный порядок | все правила убывают по порядку; поиск циклов на срезе пуст |
| «SRS не завершима» | `tfl.srs.find_cycle` | предъявлен конкретный цикл переписывания |
| «SRS локально конфлюэнтна» | критические пары | все пары сходятся |
| «T и T' эквивалентны» | фазз по схеме из `LAB-1` | 10⁴ случайных цепочек, 0 расхождений |
| «Язык АГ = вот такой» | `tfl.attr` перебор деревьев до глубины d | множество принятых слов совпадает с предикатом, `|w| ≤ N` |
| «Парсеры эквивалентны» | `tfl.fuzz` дифференциально | 0 расхождений на двух пулах |

**Правило журнала:** в отчёт идёт не только вердикт, но и параметры проверки
(N, число слов, seed). Утверждение без указанной проверки помечается
`[НЕ ПРОВЕРЕНО]` — и это честнее, чем молча выдать его за факт.

### L2 — доказательные обязательства

Машинная проверка на конечном срезе не есть доказательство. Для каждого
качественного утверждения требуется:

- **Нерегулярность / не-КС**: указан конкретный свидетель (семейство слов
  с параметром), указана регулярка для пересечения (если используется),
  разобраны **все** случаи разбиения, включая **отрицательную накачку (i = 0)**.
- **Минимальность**: таблица классов с явными префиксами и суффиксами,
  различающими каждую пару состояний.
- **Недетерминированность**: для каждого недетерминированного перехода —
  пара слов с общим длинным префиксом и расходящимся поведением стека
  (прямое требование `LAB-3`).
- **Не-LL(k)**: предъявлены два слова с одинаковым lookahead длины k
  и разными продолжениями; показано, как подмена нижнего элемента стека
  выводит из языка (схема из `RK2_probe_tasks_solutions.pdf`).
- **Завершимость**: назван фундированный порядок и показано убывание
  для каждого правила.
- **Ответ «нет» на теоретический вопрос**: предъявлен контрпример.

### L3 — рубрика баллов

Прогнать решение по разбалловке (`consa_rk2_2024.pdf`, §РК2 в таксономии)
и посчитать ожидаемый балл. Отдельно проверить «дешёвые» пункты, которые
легко забыть:

- префикс-свойство (+1 почти всегда);
- доказательство нерегулярности, если язык КС (+1);
- анализ дополнения, если язык не DCFL (почти всегда даёт баллы);
- оформление в Markdown/LaTeX (+1, перманентно);
- дополнительные задания «Аптеки» по теме.

Если базовая гипотеза не доказана до конца — применить лайфхаки: частичный
результат («не смог доказать не-КС, но доказал не-DCFL») стоит баллов,
и это надо явно писать в отчёте, а не выбрасывать.

## 7. План по сессиям

Работа рассчитана на несколько сессий; каждая заканчивается проверяемым
артефактом. Состояние переносится через файлы, а не через контекст.

| Сессия | Задача | Артефакт | Готово, когда |
|---|---|---|---|
| **S-0** ✅ | Инвентаризация корпуса, таксономия, план | `docs/01..03`, `tools/extract_corpus.py`, `corpus/` | сделано 2026-09-05 |
| **S-1** ✅ | Ядро оракулов: регексы, автоматы, Майхилл–Нероуд | `tfl/{regex,automata,myhill,words}.py`, `tests/test_core.py` (162 теста), `evals/lab2_2025_report.md` | сделано 2026-09-06: все 28 регексов разбираются, два независимых построения ДКА совпадают на всех вариантах, сверка с `dm800` (вар. 15) и `Prrromanssss` (вар. 2) сошлась |
| **S-2** ✅ | Первый сквозной прогон: `LAB-2` целиком на известном варианте | `tfl/glushkov.py`, `tools/lab2_report.py`, `docs/recipes/LAB-2.md`, `reports/lab2-variant-15/` | сделано 2026-09-06: ДКА, таблица классов и НКА варианта 15 совпали с `dm800`; их упрощение расширенной регулярки проверено оракулом и оказалось верным |
| **S-3** | SRS-ядро + `LAB-1` | `tfl/srs.py`, `docs/recipes/LAB-1.md` | на варианте 20 воспроизведён вывод `boomhaa/report_lab1.md` (включая цикл незавершимости) |
| **S-4** | Грамматики, PDA, LL/LR + `LAB-3` | `tfl/cfg.py`, `tfl/pda.py`, `tfl/parse.py` | LL(1)/LR(0)-таблицы сходятся с Grammophone на 10 грамматиках |
| **S-5** | Атрибутные грамматики + `RK2-C` | `tfl/attr.py`, `docs/recipes/RK2-*.md` | воспроизведены оба разбора из `RK2_probe_tasks_solutions.pdf` |
| **S-6** | Накачки и предикаты языков + `RK1-*` | `tfl/lang.py`, `tfl/pump.py`, рецепты РК1 | воспроизведены все 4 разбора из `RK1_probe_task_solutions.pdf` |
| **S-7** | Сборка скилла | `.claude/skills/tfl/SKILL.md` + подскиллы | по новой задаче цикл S0–S7 проходит без ручного вмешательства |

**Порядок неслучаен:** сначала регулярные языки (там оракул тотальный и
дешёвый), потом КС (оракул частичный), потом не-КС (оракул только
опровергающий). Так каждая следующая сессия опирается на уже проверенный слой.

## 8. Как измерять, что агент работает

Три метрики на eval-наборе (`Pharma_*` + экзаменационные билеты + варианты,
для которых есть решения в слое C):

1. **Доля L1-чистых решений** — гипотеза пережила машинную проверку
   с первой попытки. Целевой ориентир: > 70 % для регулярных задач,
   > 40 % для не-КС.
2. **Доля пойманных собственных ошибок** — сколько гипотез было отвергнуто
   оракулом до того, как попасть в отчёт. Чем выше, тем лучше: это и есть
   работа, ради которой строится слой T.
3. **Ожидаемый балл по L3** против фактического балла старшекурсника
   на том же варианте.

Метрика 2 — важнейшая. Агент, который никогда не отвергает свои гипотезы,
не проверяет их.

## 9. Открытые вопросы

1. **Номер варианта.** Без него нельзя выбрать задачу ни в одной лабе,
   ни в РК. Нужен номер в списке группы.
2. **Год заданий.** На 2026-09-05 опубликованы задания 2025; если курс
   стартует сейчас, задания 2026 появятся в ближайшие недели. До их выхода
   разработка ведётся на материале 2025 — это корректно, структура заданий
   устойчива с 2024 года.
3. **Язык реализации кода лаб.** Оракулы `tfl/` пишем на Python (быстро,
   без сборки). Но сдаваемый код лабы может требоваться на другом языке —
   у текущего потока преобладает Rust. Нужно решить: сдавать Python или
   портировать.
4. **Глубина автоматизации ЛР4.** Бенчмарки и графики скорости требуют
   реального прогона; это уже не «оракул», а полноценная реализация.
