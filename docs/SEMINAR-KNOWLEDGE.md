# Пополнение памяти семинаров

## Где хранить

```text
references/seminar/YYYY-MM-DD.txt   сырой локальный текст пользователя
corpus/seminars/index.jsonl         короткие проверенные карточки методов
tests/test_*.py                     исполняемые регрессии общих утверждений
docs/recipes/*.md                   устойчивый рецепт, если появился новый класс
```

Дата файла — дата официального занятия. Если за день несколько файлов,
используются суффиксы `YYYY-MM-DD-01.txt`, `YYYY-MM-DD-02.txt`. Дата отмечает,
что тема к этому моменту уже пройдена; отдельный глобальный флаг
`current_week` не нужен и быстро устаревает.

Сырьё в `references/` локально и не публикуется. В Git попадает только
обезличенная карточка, достаточная для распознавания метода, объяснения и
независимой проверки.

## Статусы

- `raw` — задача выделена, решение ещё не проверено;
- `partial` — есть полезный приём, но осталось обязательство;
- `verified` — формулировка, метод и границы проверены; только этот статус
  используется автоматическим поиском аналогов.

## Еженедельный цикл

1. Прочитать все новые `references/seminar/*.txt` по дате.
2. Разделить файл на самостоятельные задачи; не смешивать подпункты с разными
   методами.
3. Для каждой задачи записать глобальный объект, вопрос, признаки выбора
   метода и два-три малых приёма.
4. Сначала проверить решение существующими оракулами. Новый исполняемый код
   добавлять только для устойчивого пробела.
5. Превратить частный разбор в общий обезличенный урок и добавить регрессию.
6. Добавить строку в `corpus/seminars/index.jsonl`; перевести в `verified`
   только после независимой проверки.
7. Запустить `py -3 -m tfl intake --mode training` на формулировке задачи:
   нужная карточка должна появиться в разделе семинарских аналогов.
8. Для нового устойчивого типа добавить обычную регрессию; замороженный
   `pedagogy_holdout` не менять без выпуска следующей версии его manifest.
9. Обновить `PROJECT-STATE.md`; незакрытое обязательство сразу добавить в
   `OPEN-GAPS.md`.

## Как применять к новой задаче

В тренировочном режиме семинарская карточка — первая гипотеза, не доказательство
и не разрешение копировать ответ. Нужно проверить:

- совпадает ли формальный объект;
- совпадает ли вопрос;
- работают ли те же малые признаки;
- не нарушена ли предпосылка знакомого метода;
- можно ли проверить новый объект тем же оракулом.

Если совпадают только отдельные шаги, агент переносит именно их и прямо
говорит, где начинается новая часть. Если подходящего аналога нет, маршрут
переходит к предметному рецепту и полному корпусу.

## Совместимость со слабыми моделями

Карточка должна быть самодостаточной, короткой и использовать фиксированные
поля. Нельзя требовать, чтобы модель восстановила метод из длинного отчёта.
Предпочтительны буквальные признаки (`есть дизъюнкция трёх условий`, `правило
сохраняет число b`) и исполняемая команда проверки. Один идентификатор означает
один метод; неоднозначные формулировки делятся на несколько карточек.
