## Шаг 1. Разбор и нумерация (4 балла)

```
[rg]  ::= [rg][rg] | [rg]|[rg] | ([rg]) | (?:[rg]) | [rg]* | (?[num]) | \[num] | [a-z]
[num] ::= [1-9]
[rg]  ::= (?=[rg])      # в части вариантов
```

```python
from tfl.extre import parse_extended, groups, validate

node = parse_extended("((?:a(?2)|(bb))(?1))")
groups(node)          # {1: …, 2: …} — тела групп по номерам
validate(node)        # Verdict: корректно или почему нет
```

**Нумерация — по номеру открывающей скобки слева направо, и считаются
только скобки захвата.** `(?:…)`, `(?=…)` и сами ссылки `(?N)` номеров
не занимают. Проверить легко: в `((?:a(?2)|(bb))(?1))` вторая группа —
это `(bb)`; иначе вердикт преподавателя «захват выражения из другой
альтернативы» не имел бы смысла.

Ограничения условия, все три проверяются `validate`:

* групп захвата не больше девяти;
* опережающая проверка не содержит групп захвата;
* опережающие проверки не вкладываются друг в друга.

## Шаг 2. Инициализированность ссылок — главное место задания

Два вида ссылок ведут себя по-разному, и это ровно то, на чём валятся:

> Ссылки на выражения **априори всегда инициализированы**. Т.е. `(?1)(a|b)` —
> корректное выражение… Выражение `(\1)(a|b)` некорректно, потому что
> здесь, чтобы понять, что подставлять вместо ссылки, нужно уже распарсить
> префикс, зайдя в группу захвата.

Правило: **`(?N)` корректна всегда; `\N` — только если группа `N` дочитана
до конца по всем путям разбора.**

Отсюда три следствия, которые надо проверять явно:

1. **Альтернатива режет.** В `(a|(bb))\2` на пути `a` группа 2 не заполнена,
   значит выражение некорректно. Формально: после `Alt` инициализированными
   считаются только те группы, что заполнены в **каждой** ветви.
2. **Звёздочка не даёт ничего.**

   > Группа захвата, если окажется под звёздочкой, то допустит хотя бы один
   > путь разбора такой, что на нём она не будет инициализирована.

   Поэтому `(?1)(a|b)*(?1)` можно, а `(a|b)*\1` уже нет.
3. **Ссылку на выражение надо раскрыть на месте.** В `(a|(?2))(a|(bb\1))`
   ошибка видна только после подстановки тела второй группы внутрь первой:
   там `\1` обращается к ещё не дочитанной группе 1.

Левая рекурсия (`((?1)a|b)`) **синтаксически корректна**, хотя разбор по ней
в настоящих машинах регексов падает. Отвергать её нельзя.

Все двенадцать вердиктов преподавателя из issue #35 воспроизводятся
оракулом — `tests/test_extre.py`.

## Шаг 3. КС-грамматика каркаса (до 8 баллов)

> Построить контекстно-свободную грамматику, которая описывает каркас
> регулярного выражения. Заменить ссылки на группы захвата свежими
> нетерминалами.

```python
from tfl.extre import skeleton_cfg
from tfl.parse import recognize

grammar = skeleton_cfg(parse_extended("(a(?1)b|c)"))
recognize(grammar, "aacbb")     # True
```

**Где каркас точен, а где шире языка.** Если в выражении нет `\N`
и опережающих проверок, каркас задаёт язык **точно**: ссылка на выражение —
это в точности рекурсия в грамматике. Со ссылкой на строку каркас
**шире**: он допускает любое слово группы вместо ровно того, что она
захватила. Опережающая проверка стирается в ε, что тоже расширяет.

Вывод из каркаса поэтому односторонний, как и во всех приближениях сверху
(`tfl/approx.py`): `False` доказывает, что слово в язык не входит,
`True` не доказывает ничего.

**Проверенная опечатка в условии.** Там написано, что `(a(?1)b|c)` —
регекс для языка `{aⁿcⁿbⁿ}`. На самом деле это `{aⁿ c bⁿ}`: грамматика
каркаса `G → a G b | c` точна (ссылок на строку нет), и она порождает
именно такой язык. Иначе и быть не может — выражение с одними лишь
ссылками на выражение задаёт КС-язык, а `{aⁿcⁿbⁿ}` не контекстно-свободен.

## Шаг 4. Атрибутная грамматика (до 10 баллов)

> Добавить атрибуты для учёта ограничений на количество групп захвата
> и проверки использования ссылок и их инициализации.

Анализ из шага 2 — это ровно вычисление атрибутов, и записывается он
в нотации курса:

* **синтезируемый** атрибут «номер последней группы» — считает захваты
  слева направо и даёт нумерацию;
* **синтезируемый** «множество групп, дочитанных к концу подвыражения» —
  объединение для конкатенации, **пересечение** для альтернативы, пустое
  для итерации;
* **наследуемый** «множество групп, дочитанных до входа в подвыражение» —
  он и проверяет `\N`.

Инструмент — `tfl/attr.py`: он умеет и синтезируемые, и наследуемые
атрибуты, перебирает деревья вывода и проверяет гипотезы об атрибутах
(`check_attribute`).

## Шаг 5. Тестовый цикл (15 баллов)

> Организовать тестовый цикл: ввести слова для проверки; проверить,
> входят ли они в язык, определяемый регексом.

```python
from tfl.extre import matches
matches(parse_extended("(aa|bb)(?1)"), "bbaa")     # True
```

Для выражений со ссылками на строку одного каркаса мало: он даёт ответ
сверху. Точная проверка требует хранить захваченные подстроки при разборе —
это и есть отличие полного выполнения от восьмибалльного.

## Границы выводов

| Вывод оракула | Что он значит |
|---|---|
| `validate` вернул «корректно» | **доказано**: все ограничения условия выполнены |
| `validate` вернул «некорректно» | **доказано**: названа конкретная нарушенная ссылка |
| каркас принял слово, ссылок на строку нет | **доказано**: слово в языке |
| каркас принял слово, ссылки на строку есть | **ничего**: каркас шире языка |
| каркас отверг слово | **доказано**: слова в языке нет |

## Чего не делать

* Не отвергать левую рекурсию: она синтаксически корректна.
* Не считать `(?:…)` и `(?=…)` за группы при нумерации.
* Не выдавать ответ каркаса за ответ про язык, если в выражении есть `\N`.
* Не переписывать пример `(a(?1)b|c)` из условия вместе с его языком:
  там опечатка.
