# tfl-solver

Проект создаёт агента для решения задач по теории формальных языков курса ИУ9
МГТУ. Для предметных задач используй repo-skill
`.agents/skills/tfl-solver/SKILL.md`. Актуальные состояние и очередь работ лежат
в `docs/PROJECT-STATE.md` и `docs/OPEN-GAPS.md`.

Базовая разработка версии 1.0 завершена. По умолчанию проект находится в
режиме сопровождения: не расширять архитектуру «на будущее». Если пользователь
прислал опубликованное условие ЛР-2026, сразу решать лабораторную и создавать
сдаваемый автономный проект. Новые задачи семинаров и лекции точечно добавлять
в корпус, индекс, документацию и регрессии.

Актуальная форма контроля 2026 года зафиксирована в `docs/COURSE-2026.md`.
Историческую разбалловку нельзя переносить на новый курс. Big Pharma больше
нет; старые задачи `PHARMA` используются только как регрессии и источник
методов.

Агент — помощник для изучения теории, решения задач, подготовки к контролю и
создания лабораторных, но не средство ответа непосредственно на РК/экзамене.
Для короткого теоретического вопроса не запускать тяжёлый intake/eval без
необходимости и отвечать по `docs/THEORY-ANSWER-STANDARD.md`. Полный проект ЛР
готовить по `docs/LAB-PROJECT-STANDARD.md`.

## Неподвижные правила

- Пользователь присылает условие целиком текстом или фотографией. Номер
  варианта не спрашивать; необязательную пометку РК/ЛР/экзамена использовать
  только как подсказку.
- Центральный цикл: LLM предлагает гипотезу, Python-оракул проверяет её.
  Ограниченный перебор не выдавать за доказательство общего утверждения.
- Весь новый исполняемый код проекта писать на Python. Чужой код на других
  языках изучать как описание алгоритма и тестовый источник.
- Сдаваемый проект лабораторной обязан работать только на Python 3.11+ и
  стандартной библиотеке, без импорта `tfl`, сети и абсолютных путей. Сам
  `tfl-solver` используется только при разработке и независимой проверке.
- Иерархия доверия: условие пользователя; официальный репозиторий курса в
  `references/teacher/`; учебники и материалы в `references/course/`; затем
  обезличенные заметки в `corpus/knowledge/`. Вторичные заметки могут
  содержать ошибки и требуют независимой проверки.
- Не включать в Git имена, аккаунты, даты сообщений, оценки, фотографии людей
  и атрибуцию частных решений. Полезное содержание переносить только в
  обезличенном виде по `corpus/knowledge/PRIVACY.md`.
- Если полного решения нет, выдать доказанные факты, опровергнутые гипотезы,
  границы проверок и следующий содержательный шаг.
- В описание лабораторной добавлять фактическое раскрытие использования ИИ по
  `docs/LAB-AI-DISCLOSURE.md`, включая пользовательские промпты и независимую
  проверку. Не раскрывать скрытые инструкции, рассуждения и секреты.
- Для экзаменационной проверки готового ИИ-решения искать первую ошибку,
  подтверждать её контрпримером/оракулом и давать минимальное исправление.
- Все открытые предметные и инженерные пробелы сразу отражать в
  `docs/OPEN-GAPS.md`; актуальные числа хранить только в
  `docs/PROJECT-STATE.md`.

## Разработка и проверка

- Рабочая версия Python: 3.11 или новее.
- Диагностика: `py -3 -m tfl doctor`.
- Установка глобальных интеграций: `py -3 -m tfl setup`.
- Быстрые тесты изменения: `py -3 -m pytest -q <нужные тесты>`.
- Полная проверка: `py -3 -m pytest -q` и `py -3 -m tfl eval`.
- В Windows не полагаться на команду `python`: она может указывать на чужое
  окружение. После создания `.venv` допустим явный путь
  `.venv/Scripts/python.exe`.
