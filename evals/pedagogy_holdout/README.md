# Педагогический holdout

Набор проверяет не только правильный глобальный класс, но и путь до основного
метода: зацепку в условии, небольшое действие, полученный результат, следующий
выбор и корректный перенос семинарского аналога. Он отделён от замороженного
`agent_holdout` v1 и не изменяет его исторические оценки.

Восемь случаев покрывают:

- пять прямых переносов методов семинара;
- два тренировочных переноса отдельных малых приёмов;
- один полный режим с аудитом уровней инъективности.

Запуск реальной LLM выполняется только явно:

```powershell
py -3 -m tfl pedagogy list
py -3 -m tfl pedagogy prompt --case training-unbounded-delay
py -3 -m tfl pedagogy run --runner codex --case training-unbounded-delay `
  --output reports/pedagogy/codex-delay.jsonl
py -3 -m tfl pedagogy score --input reports/pedagogy/codex-delay.jsonl
```

Scorer оценивает режим, класс, аналог, наличие хотя бы двух полных связанных
шагов открытия, малые приёмы, основной метод, выбор и фактический запуск
оракула, содержательные опоры ответа и отсутствие запрещённого
педагогического сокращения. Регулярные выражения рубрики скрыты от запускаемой
модели.

Версия 2, ревизия рубрики 6 требует поле `discovery_path`, проверяет его на
известные содержательные ошибки и отдельно показывает содержательный PASS и
соблюдение бюджета; номер ревизии и хеш
случаев находятся в `manifest.json`. Первый Codex baseline 8/8 PASS и 104/104
был снят на версии 1, ревизии 4, поэтому остаётся историческим и не считается
baseline новой рубрики. Полный исторический отчёт —
`reports/pedagogy/codex-baseline-2026-09-28.md`.
