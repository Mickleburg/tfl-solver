# Сквозной holdout агента

Набор проверяет не отдельный Python-оракул, а наблюдаемую траекторию агента:

```text
сырое условие → класс и рецепт → формализация → вызов оракула
               → доказательные статусы → итоговый ответ
```

Семь задач взяты из источников 2021–2025 и не совпадают с исполняемыми
случаями `evals/suite.py`. Условия исправляют только очевидные артефакты OCR.
Ожидаемый класс, допустимые семейства оракулов и смысловые опорные точки не
передаются агенту. `manifest.json` фиксирует число случаев и SHA-256 текста с
нормализованными LF, поэтому набор нельзя незаметно подправить после запуска.

## Запуск

Показать состав набора и сформировать одиночный prompt:

```powershell
py -3 -m tfl holdout list
py -3 -m tfl holdout prompt --case pharma-2022-A11
```

Запустить установленный Codex в read-only sandbox и сохранить машинный
транскрипт. Один или несколько `--case` обязательны; полный прогон требует
явного `--all`, чтобы случайно не потратить бюджет всех задач:

```powershell
py -3 -m tfl holdout run `
  --case pharma-2022-A11 --output reports/agent-holdout/codex-smoke.jsonl
```

Оценить сохранённый прогон:

```powershell
py -3 -m tfl holdout score `
  --input reports/agent-holdout/codex-smoke.jsonl `
  --report reports/agent-holdout/codex-smoke.md
```

Codex вызывается через `codex exec --ephemeral --sandbox read-only
--output-schema ... --json`. Harness сохраняет только финальный структурный
ответ, выполненные команды, usage и ошибку запуска; скрытые рассуждения в
артефакт не попадают.

Первый зафиксированный smoke-run: `reports/agent-holdout/codex-smoke-2026-09-12.md`.
Он прошёл 10/10, но показал слишком длинную траекторию; поэтому prompt теперь
ограничивает агента десятью командами и запрещает чтение больших файлов целиком.

## Оценка

Всего 10 баллов:

- 2 — правильный класс;
- 1 — правильный рецепт;
- 1 — полная формализация условия;
- 1 — подходящее семейство оракулов;
- 1 — наблюдаемый фактический запуск команды;
- 1 — свидетель для каждого утверждения;
- 1 — честная граница доказательства;
- 2 — смысловые опорные точки ответа.

Порог — 8 баллов; неправильный класс, отсутствие наблюдаемой команды или
превышение записанного в run бюджета команд не могут пройти независимо от
суммы. Scorer не заменяет предметного рецензента: он ловит пропущенные стадии,
неподходящий оракул и выдачу конечного среза за доказательство. Новые неверные
траектории после ручной проверки превращаются в отдельные регрессионные
правила.
